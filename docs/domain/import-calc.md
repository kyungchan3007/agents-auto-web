# 직구 계산기

## 용어
| 용어 | 뜻 |
| --- | --- |
| 물건 값 | 사용자가 입력하는 외화 금액 (통화 선택) |
| 원화 환산 | 물건 값 × 기준일 환율 |
| 면세 한도 · 관부가세 | 해외 직구 시 세금 기준 — 값 · 출처는 `features/import-calc/rules.ts` 한 곳 (IMP-03) |

## 불변식 (항상 참이어야 하는 것)
| ID | 규칙 | 검사 |
| --- | --- | --- |
| IMP-01 | 계산은 브라우저 안에서만 — 입력값을 어디에도 보내거나 저장하지 않는다 | `calc.ts` 순수 함수 · 화면 상태에만 (보내는 코드 없음) |
| IMP-02 | 사용한 환율의 기준일 · 출처를 결과 옆에 표시한다 | 화면 결과 아래 환율 기준일 · 출처 (`calc-form.tsx`) |
| IMP-03 | 세금 기준값(면세 한도 · 세율)은 코드에 흩지 않고 한 파일에 출처 · 기준일과 함께 둔다 | `calc.test.ts` "기준값" |
| IMP-04 | 결과는 "예상 금액"으로 표시하고, 실제 세액은 관세청 기준이라는 안내를 둔다 | 화면 안내 "예상 금액입니다" (`calc-form.tsx`) |
| IMP-06 | 이번 주(일요일 ~ 토요일) 관세청 과세환율이 있는 통화는 그 값으로 계산하고 출처 · 고시 주를 표시한다. 없거나 지난 주 값이면 수출입은행 환율 + "예상 금액" 안내로 돌아간다 | `customs-rate.test.ts` "pickRate" |
| IMP-05 | 음수 · 숫자 아닌 입력은 계산하지 않고 이유를 보여 준다 | `calc.test.ts` "틀린 입력은 계산하지 않고 이유" |

## 확인함 (2026-10-29 · 작업 0059)
- 출처: [관세청 해외직구물품 예상세액 조회](https://www.customs.go.kr/kcs/ad/tax/BuyTaxCalculation.do)
- 면세 한도: 목록통관 미화 150달러 이하 (미국 200달러 이하) · 일반통관(수입신고) 150달러 이하
- 물품가격 = 물품대금 + 발송국 안 세금 · 내륙운임 · 보험료 · 한도를 넘으면 국제 운임까지 더한 총과세가격에 과세
- 부가세 = (과세가격 + 관세 + …) × 10%
- 관세율은 품목마다 달라 사용자가 넣음 (지어내지 않음) · 비우면 면세 여부만

## 관세청 과세환율 (작업 0163)
- 출처: 공공데이터포털 [관세청_관세환율정보(GW)](https://www.data.go.kr/data/15101230/openapi.do) · 수입(`weekFxrtTpcd=2`) · 외화 1단위당 원 · 매주 일요일 ~ 토요일 적용 (관세평가 운영에 관한 고시 제3조②)
- 수집: 평일 12:00 KST 회차에서 환율 수집이 끝난 뒤 따로 받음 · 이번 주가 이미 저장돼 있으면 호출하지 않음 · 키(`KCS_KEY`)가 없으면 건너뜀 · 실패해도 환율 수집에 영향 없음
- 저장: 공용 시계열 표 `indicator_points` (series `kcs-import:USD` · period 적용 시작일 · value) — 이후 KOSIS · ECOS 도 같은 표를 씀
- 쓰는 규칙: 이번 주 값만 계산에 씀 (낡은 값으로 세금을 어림하지 않음) · 100단위 통화(엔 등)는 수출입은행 고시 단위에 맞춰 비교
- 자료가 없으면 화면은 "준비 중" — 숫자를 만들지 않음
- **키 발급 후 확인 필요**: Cloudflare Workers 에서 실제 호출이 되는지 (해외 서버 차단 가능성) · "조회일 → 그 주 일요일이 적용 시작일" 가정

## 환율과 수입물가 (작업 0165)
- 출처: 한국은행 ECOS OpenAPI `StatisticSearch` · 통계표 `401Y015` 수입물가지수(기본분류) · 항목 `*AA` 총지수 · `W` 원화기준 · 월별 · 2020=100 · 화면에 "한국은행 ECOS 에서 제공된 정보" 표시 (약관 제7조)
- 저장: 공용 시계열 표 `indicator_points` (series `ecos-import-price:krw` · period `YYYY-MM`) · 매달 1일 회차에서 다른 월간 수집과 **따로** 최근 24개월을 다시 받아 덮어씀 · 키(`ECOS_KEY`)가 없으면 건너뜀
- 데이터 없음(`INFO-200`)도 오류로 기록 (24개월 범위에서 하나도 없으면 이상한 상황 · 가정)
- 화면 규칙: 원/달러 월평균(수출입은행 일별 평균)과 같은 달끼리 겹쳐 그림 · 두 값의 단위가 달라 "처음 같은 달 = 100" 으로 맞춤 · 한쪽만 있는 달은 비워 둠(채우지 않음) · 달별 숫자는 표로도 · 자료가 없거나 겹치는 달이 없으면 "준비 중"
- ECOS 는 다음 달 15일경 발표 · 1일 회차만 쓰므로 약 2주 ~ 한 달 반 늦게 반영
- **키 발급 후 확인 필요**: Workers(해외 IP)에서 실제 호출 · 실제 응답 모양 (공개 샘플 키로 확인한 모양을 따름)
