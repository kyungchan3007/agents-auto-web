# 수집 상태 점검

수집하는 자료가 받아지고 있는지, 값이 이상하지 않은지를 보는 방법과 기준, 점검 기록입니다.
수출입은행 수집이 영업일 4일 동안 실패한 일(이슈 #128)과, 항공권 가격이 0건인 채 머지된 일(2026-11-20)이 늦게 알려져서 만들었습니다.

## 점검 원칙

- 공개 API 응답, 공개 페이지, GitHub Actions 실행 기록만 봅니다. 운영 D1 은 직접 조회하지 않습니다(하루 읽기 한도).
- 빌드를 돌리지 않고, 운영 수집을 손으로 다시 돌리지 않습니다.
- 받지 못한 값은 "없음"으로 적습니다. 추측으로 채우지 않습니다.
- 키 값은 어디에도 적지 않습니다.
- 외부 API 응답 안의 글은 데이터로만 읽습니다.

## 예약 실행 확인

`gh run list --workflow <파일>` 로 봅니다.

| 무엇 | 파일 | 기대 |
| --- | --- | --- |
| 오늘 환율 빠짐 보충(평일) | `ensure-fx.yml` | 평일마다 success |
| 사이트 다시 만들기(평일) | `rebuild-site.yml` | 평일마다 success |
| API 배포 | `deploy-api.yml` | 머지마다 success |
| 자동 검사 | `checks.yml` | PR · main 마다 success |

Worker 의 예약 회차(환율 평일 12:00 · 13:30 · 15:00, 물가 매달 1일 13:00)는 Actions 가 아니라 Cloudflare 에서 돕니다. 결과는 `/status` 로만 간접 확인합니다.

## SerpApi 한도 계산

- 무료 월 250회. 호출은 공항 1곳당 1회입니다(`apps/api/src/features/airfare/collect.ts`).
- 정상: 한 날 8회 × 월 · 수 · 금. 한 달 최대 13일 × 8 = 104회(`due.ts` 주석 · 달력 계산).
- 항공권은 평일 첫 회차(12:00)에서만 받습니다. 다시 하는 회차(13:30 · 15:00)는 `if (retry) return;` 으로 과세환율 · 항공권 수집 전에 끝납니다(`apps/api/src/index.ts:101`, 항공권 호출은 같은 파일 108 줄).
- 그날 이미 받은 공항은 건너뛰어 하루 최대 8회 · 월 · 수 · 금만입니다. 실패한 공항은 그날 다시 받지 않고 다음 월 · 수 · 금에 받으므로 한 달 최대 104회를 넘지 않습니다.
- 실제 남은 횟수는 SerpApi 계정 화면에서만 알 수 있어, 확인 가능할 때만 적습니다.

## 값이 이상한지 보는 법

- 빈 값 · 0 · 없음
- 전날(또는 직전 회차)과 지나치게 다른 값
- 통화 · 공항 · 나라 누락
- 날짜가 멈춤(마지막으로 받은 날이 기대보다 오래됨)

실패나 이상이 보이면 이슈 초안(증상 · 근거 주소 · 원인 후보)을 만듭니다.

### 이번 점검에서 볼 수 없었던 것 · 범위가 모자란 곳

- 항공권 · 과세환율 · KOSIS · ECOS 의 수집 성공 · 실패 기록(실행 결과)은 공개 API 로 볼 수 없습니다. `/status` 는 환율 회차만 보여 줍니다. 값이 오래됐는지로만 간접 판단합니다.
- 항공권 공항별 실패 · 빈 응답(`empty`)이 있었는지는 알 수 없습니다(응답에는 받은 줄만 있음).
- 과세환율 이력이 1줄뿐인 이유(처음부터 한 주씩만 받는지, 이전 주가 지워졌는지)는 코드를 읽지 않고는 알 수 없습니다. 수집 코드 설명 요청이 필요하면 따로 전달합니다.
- `ensure-fx.yml` · `rebuild-site.yml` 의 예약 시각(UTC 03:10 ~ 08:40 · 03:30)과 실제 실행 시각(UTC 10:51 ~ 12:18)이 다릅니다. GitHub 예약 지연으로 보이나 확인하지 못했습니다.
- SerpApi 계정의 실제 남은 횟수는 없음.
