## 게이트 판정 규칙 (작업 0232 · 0239 수정 · 모든 자리 공통)
"통과" · "PASS" · "확인 끝"은 **PR 최신 커밋의 CI `gate` 가 COMPLETED + SUCCESS 하나**로 쓴다. 못 봤으면 "확인 중"이라고 쓴다.
로컬에서 돌린 것(바뀐 spec · 실패한 spec 등)은 통과의 근거가 아니라, 보고에 무엇을 돌렸는지 적는 참고다.

### 1. 로컬 확인 — 바뀐 곳 · 실패한 곳만 (참고)
- 로컬 전체 e2e · 로컬 전체 게이트는 돌리지 않는다. 전체는 CI 가 본다.
  - 로컬 e2e 는 이 작업에서 새로 쓰거나 고친 spec 파일만 돌린다(작업 0295 · 훅 `.agents/scripts/e2e-guard.mjs` 가 막음). 앞선 실행에서 실패한 것은 `--last-failed` 로 다시 돌릴 수 있다.
  - develop 으로 가는 PR 의 CI 는 e2e 를 돌리지 않는다(build 까지). 전체 e2e 는 main 으로 가는 PR 에서 CI 가 돌고, 거기서 실패한 spec 만 로컬에서 고치고 다시 푸시한다.
- 무엇을 돌렸는지(spec 이름 · 명령)를 보고에 적는다. 가짜 API(mock) · 로컬 빌드로 돌렸으면 그렇게 적는다.
- 로컬 로그를 볼 때도 `tail` · `head` 로 끝 몇 줄만 보고 판단하지 않는다.

### 2. PR 의 CI 게이트 — 최신 커밋 기준 (판정)
- `gh pr view <번호> --json headRefOid,statusCheckRollup` 에서 **최신 커밋(headRefOid)** 의 `gate` 체크를 본다.
  - 통과: `gate` 의 status 가 `COMPLETED` **이고** conclusion 이 `SUCCESS`
  - 결과 없음 · 빈 값 · `IN_PROGRESS` · `QUEUED` 는 통과가 아니다. 아직 진행 중이다.
- CI 로그를 볼 때: `grep -c "❌" 로그파일` 이 0 **이고** `결과: ✅ ALL PASS` 줄이 있어야 한다. 하나라도 `❌` 가 있으면 실패다. 마지막 줄이 무엇이든 마찬가지다(앞 단계 실패를 놓치지 않게).
- 루프 모드를 낮추지 않는다. Full 작업을 `LOOP=quick` 으로 돌린 결과는 판정 근거가 아니다.
- 미리보기 빌드(Workers Builds) 통과는 게이트 통과가 **아니다**. 둘은 따로 본다.
- 커밋을 새로 올렸으면 앞 커밋의 결과는 쓰지 않는다.

### 3. e2e 결과 기호 읽기 (playwright)
- `✘` = 실패 · `✓` = 통과 · `-` = 건너뜀(실패 아님) · `(retry #1)` 뒤에 통과 = 흔들림(통과지만 보고에 적음)
- 실패 줄은 테스트 이름과 함께 보고한다. "모두 통과"는 실패 수 0 을 본 뒤에만 쓴다.

### 4. 보고 형식 (한 줄)
- `게이트: CI gate=SUCCESS @<커밋 7자리> · 로컬 확인 <돌린 spec> · 미리보기 빌드=SUCCESS`
- 실패면: `게이트: CI gate=FAILURE @<커밋> · 실패 <테스트 이름> …` — 원인을 모르면 "원인 확인 중"

## 디자인 PR 판정 (작업 0246)
테스트는 두 종류다. **기능 테스트**(표시 없음)는 늘 막는다. **디자인 테스트**(테스트 이름에 `@design`)는 정해 둔 모양 값(좌표 · 여백 · 색 · 글꼴 · 모서리 · 그림자 · 배치 순서 · 정렬 · 움직임의 시작과 끝 모양)을 본다. 사용자가 정한 조건("첫 화면에 들어온다" · "가로로 넘치지 않는다" · "값이 바뀌어도 밀리지 않는다")은 모양처럼 보여도 기능 테스트다. 헷갈리면 표시하지 않는다(막는 쪽이 안전).

새 테스트를 쓸지는 team.md test 절 "작업 종류" 구분을 따른다(작업 0297): 보이는 값만 바뀌는 작업(색 · 모서리 · 투명도 · 그림자 · 테두리)과 크기 · 간격 · 위치만 바뀌는 작업은 새 테스트를 쓰지 않고, 숫자 · 동작 · 문구 규칙이 바뀌거나 사용자가 새 조건을 붙인 작업만 기능 테스트를 새로 쓴다.

**디자인 PR** = PR 에 `design` 라벨이 있고 **그리고** 바뀐 파일이 모두 화면 쪽(허용 목록: `.agents/scripts/design-pr.mjs`)일 때. 라벨만 있고 다른 파일이 섞이면 평소 PR 이고 "design 라벨인데 이 파일이 섞였다" 경고 줄이 난다. 라벨이 없거나 읽지 못하면 평소 PR 이다.

| PR 종류 | 기능 테스트 | 디자인 테스트(`@design`) |
| --- | --- | --- |
| 평소 PR | 실패하면 막음 | 실패하면 막음 |
| 디자인 PR | 실패하면 막음 | 돌리되 막지 않고 실패 목록만 남김 |
| 하루 마무리 PR(develop → main) — 그날 디자인 PR 뿐 | 실패하면 막음 | 돌리되 막지 않고 목록만 남김 |
| 하루 마무리 PR — 평소 PR 이 하나라도 섞임 | 실패하면 막음 | 실패하면 막음 |

- 디자인 테스트를 끄지 않는다. 돌려서 실패 목록을 로그에 한 묶음("막지 않음")으로 남긴다. 그 목록은 `docs/design-tests-pending.md` 에 쌓는다.
- e2e 는 main 으로 가는 PR 에서만 돈다(develop PR 은 e2e 없음 · 작업 0295). 디자인 PR 판정으로 달라지는 것은 `@design` 실패가 막느냐뿐이다.
- 하루 마무리 PR 에는 lead 가 그날 develop 에 머지된 PR 이 모두 design 일 때만 `design` 라벨을 단다. 게이트는 main...develop 구간 바뀐 파일도 허용 목록 안인지 다시 보므로 잘못 달아도 평소 규칙으로 떨어진다.
- `design` 라벨은 PR 을 열 때 단다(나중에 달면 다음 푸시부터 반영). 동작을 바꾸는 변경에는 달지 않는다.
- 판정 줄: `디자인 PR: 예 · 디자인 테스트 실패 N개(막지 않음)` / `디자인 PR: 아니오(이유)`. 완료 판단은 그대로 PR 최신 커밋의 CI `gate` 하나다.
