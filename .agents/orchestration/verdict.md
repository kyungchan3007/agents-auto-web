## 게이트 판정 규칙 (작업 0232 · 0239 수정 · 모든 자리 공통)
"통과" · "PASS" · "확인 끝"은 **PR 최신 커밋의 CI `gate` 가 COMPLETED + SUCCESS 하나**로 쓴다. 못 봤으면 "확인 중"이라고 쓴다.
로컬에서 돌린 것(바뀐 spec · 실패한 spec 등)은 통과의 근거가 아니라, 보고에 무엇을 돌렸는지 적는 참고다.

### 1. 로컬 확인 — 바뀐 곳 · 실패한 곳만 (참고)
- 로컬 전체 e2e · 로컬 전체 게이트는 돌리지 않는다. 전체는 CI 가 본다.
  - Full 작업: 바뀐 화면의 spec 과 실패한 spec 만 로컬에서 돌린다(`--last-failed` · spec 이름 지정). CI 에서 실패한 spec 만 로컬에서 고치고 다시 푸시한다.
  - Quick 작업: 화면을 바꿨으면 그 화면의 spec 만 로컬에서 돌린다. 단위 · typecheck · lint 는 CI 가 돈다.
- 무엇을 돌렸는지(spec 이름 · 명령)를 보고에 적는다. 가짜 API(mock) · 로컬 빌드로 돌렸으면 그렇게 적는다.
- 로컬 로그를 볼 때도 `tail` · `head` 로 끝 몇 줄만 보고 판단하지 않는다.

### 2. PR 의 CI 게이트 — 최신 커밋 기준 (판정)
- `gh pr view <번호> --json headRefOid,statusCheckRollup` 에서 **최신 커밋(headRefOid)** 의 `gate` 체크를 본다.
  - 통과: `gate` 의 status 가 `COMPLETED` **이고** conclusion 이 `SUCCESS`
  - 결과 없음 · 빈 값 · `IN_PROGRESS` · `QUEUED` 는 통과가 아니다. 아직 진행 중이다.
- CI 로그를 볼 때: `grep -c "❌" 로그파일` 이 0 **이고** `결과: ✅ ALL PASS` 줄이 있어야 한다. 하나라도 `❌` 가 있으면 실패다. 마지막 줄이 무엇이든 마찬가지다(앞 단계 실패를 놓치지 않게).
- 루프 모드를 낮추지 않는다. Full 작업을 `LOOP=quick` 으로 돌린 결과는 판정 근거가 아니다.
- 미리보기 빌드(Workers Builds) 통과는 게이트 통과가 **아니다**. 둘은 따로 본다.
- 커밋을 새로 올렸으면 앞 커밋의 결과는 쓰지 않는다.

### 3. e2e 결과 기호 읽기 (playwright)
- `✘` = 실패 · `✓` = 통과 · `-` = 건너뜀(실패 아님) · `(retry #1)` 뒤에 통과 = 흔들림(통과지만 보고에 적음)
- 실패 줄은 테스트 이름과 함께 보고한다. "모두 통과"는 실패 수 0 을 본 뒤에만 쓴다.

### 4. 보고 형식 (한 줄)
- `게이트: CI gate=SUCCESS @<커밋 7자리> · 로컬 확인 <돌린 spec> · 미리보기 빌드=SUCCESS`
- 실패면: `게이트: CI gate=FAILURE @<커밋> · 실패 <테스트 이름> …` — 원인을 모르면 "원인 확인 중"
