## 게이트 판정 규칙 (작업 0232 · 모든 자리 공통)
"통과" · "PASS" · "확인 끝"은 아래 두 가지를 **둘 다** 확인했을 때만 쓴다. 하나라도 못 봤으면 "확인 중"이라고 쓴다.

### 1. 로컬 게이트 — 로그 전체에서 판정
- `bash .agents/checks.sh > 로그파일 2>&1` 로 남기고, **로그 전체**를 검사한다. `tail` · `head` 로 끝 몇 줄만 보고 판정하지 않는다.
  - 통과: `grep -c "❌" 로그파일` 이 0 **이고** `결과: ✅ ALL PASS` 줄이 있음
  - 하나라도 `❌` 가 있으면 실패다. 마지막 줄이 무엇이든 마찬가지다(앞 단계 실패를 놓치지 않게).
- 루프 모드를 낮추지 않는다. Full 작업을 `LOOP=quick` 으로 돌린 결과는 판정 근거가 아니다.
- 가짜 API(mock) · 로컬 빌드로 돌렸으면 보고에 그렇게 적는다. 최종 판정은 2(CI)로 한다.

### 2. PR 의 CI 게이트 — 최신 커밋 기준
- `gh pr view <번호> --json headRefOid,statusCheckRollup` 에서 **최신 커밋(headRefOid)** 의 `gate` 체크를 본다.
  - 통과: `gate` 의 status 가 `COMPLETED` **이고** conclusion 이 `SUCCESS`
  - 결과 없음 · 빈 값 · `IN_PROGRESS` · `QUEUED` 는 통과가 아니다. 아직 진행 중이다.
- 미리보기 빌드(Workers Builds) 통과는 게이트 통과가 **아니다**. 둘은 따로 본다.
- 커밋을 새로 올렸으면 앞 커밋의 결과는 쓰지 않는다.

### 3. e2e 결과 기호 읽기 (playwright)
- `✘` = 실패 · `✓` = 통과 · `-` = 건너뜀(실패 아님) · `(retry #1)` 뒤에 통과 = 흔들림(통과지만 보고에 적음)
- 실패 줄은 테스트 이름과 함께 보고한다. "모두 통과"는 실패 수 0 을 본 뒤에만 쓴다.

### 4. 보고 형식 (한 줄)
- `게이트: 로컬 ✅ <모드> (❌ 0개) · CI gate=SUCCESS @<커밋 7자리> · 미리보기 빌드=SUCCESS`
- 실패면: `게이트: CI gate=FAILURE @<커밋> · 실패 <테스트 이름> …` — 원인을 모르면 "원인 확인 중"
