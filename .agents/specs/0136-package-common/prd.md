# PRD — 무엇을 · 왜

> 원문(request.md)을 옮긴 파생 문서. 요구 충족 판정 기준은 언제나 원문이다

## 문제
- 같은 표 · 페이지 머리 · 숫자 표기 · 날짜 표기 · 데이터 받기 코드가 기능 폴더마다 복사되어 있습니다.
- 한 곳을 고치면 나머지가 어긋날 수 있습니다.

## 목표
- 두 곳 이상에서 쓰는 화면은 `@hav/ui`, 로직과 API 받기는 `@hav/shared` 에 둡니다.
- 화면에 보이는 값과 API 응답은 바꾸지 않습니다.

## 비목표
- 한 파일에서만 쓰는 코드는 옮기지 않습니다.
- 이름만 비슷하고 모양이 다른 코드는 억지로 합치지 않습니다.
- 새 패키지 · 새 의존성 · 디자인 변경은 하지 않습니다.

## 애매한 곳
- "패키지화" 는 기존 `@hav/ui` · `@hav/shared` 로 옮기는 것으로 봅니다 (가정: 공통 코드 양이 새 패키지를 만들 만큼 많지 않음).
- "API" 는 화면이 API 를 받는 공통 코드와 API 서버 라우트의 날짜 계산으로 봅니다 (가정).
