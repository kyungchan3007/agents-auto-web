> # 깨진 빌드는 배포하지 않기 (환율 수집 뒤 다시 빌드)
>
> ## 요청 원문
> - 그리고 이제 부터  환율정보 받아 오는 작업할때 잠시 점검중입니다. 저거를 띄우고 완료되면 다시 정상 빌드 하고 이렇게 가자
> - (claude-desktop: 매일 점검 화면은 하루 몇 분씩 사이트가 꺼지고 깨진 빌드는 못 막는다고 설명 → 두 안 제시) 깨진 빌드만 막기
>
> ## 지금
> - 평일 12:00 KST 쯤 API 가 환율을 D1 에 저장 → `rebuild-site.yml`(03:30 UTC) 이 Workers 배포 후크로 사이트를 다시 빌드.
> - 빌드 때 API 를 못 읽거나 값이 비면 화면이 "아직 받지 못했습니다" 로 빌드되고 그대로 운영에 나감.
> - Workers Builds 는 빌드 명령이 실패하면 배포하지 않고 이전 버전을 그대로 둠 → 이것을 이용.
>
> ## 만들 것
> 1. 빌드 끝에 "데이터 검사" 단계(예: `apps/web/scripts/check-build-data.*`, 빌드 명령에 연결):
>    - 빌드가 받은 핵심 데이터가 정상인지 확인: 오늘 환율(fx latest) 받기 성공 · 통화 수가 0 아님 · 기준일이 API 가 아는 가장 최근 영업일과 같음(주말 · 공휴일엔 직전 영업일이면 정상 — 날짜를 지어내지 않고 API 가 준 날짜로 비교).
>    - 신호(signal) · 항공료 지수 등 첫 페이지가 쓰는 다른 핵심 값도 "받기 실패"면 실패로 볼지 sdd 에서 정함(최소: 환율).
>    - 실패면 이유를 한 줄로 출력하고 0 이 아닌 코드로 끝냄 → Workers Builds 가 배포하지 않음 → 운영은 어제 정상 화면 유지.
>    - 운영 빌드(main)에서만 막고, 브랜치 미리보기 빌드에서는 경고만(미리보기가 막히면 작업 확인이 안 됨).
> 2. 실패를 알게 하기: 막힌 날 사람이 알 수 있게(예: rebuild-site 워크플로가 배포 결과를 확인해 실패면 Actions 요약 · 이슈 댓글 등). 방법은 sdd. 새 유료 서비스 없음.
> 3. 다시 시도: 수집이 늦게 끝난 날을 위해 rebuild 를 한 번 더(예: 05:30 UTC) 돌리거나, ensure-fx 가 오늘 값을 채웠을 때 다시 빌드를 부르는 방법 중 하나. GitHub 예약 지연은 고치지 않음(사용자 결정 · 비용 없음).
>
> ## 하지 않음
> - 수집 · 빌드 때 점검 화면을 띄우지 않음(사용자 결정). 점검 화면은 비상용 수동(작업서 `.tmp/maintenance/task.md`)만.
> - 받지 못한 숫자를 지어내지 않음.
>
> ## 테스트 (test)
> - 검사 스크립트 단위: 정상 · 환율 받기 실패 · 통화 0개 · 기준일이 API 최근 영업일보다 오래됨 · 주말(직전 영업일이면 통과) · 미리보기 모드는 경고만.
> - 운영 Worker 를 건드리지 않고 확인.
