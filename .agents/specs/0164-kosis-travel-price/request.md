1. 관세청 과세환율 (직구) — 관세청이 매주 고시하는 환율. 직구 관세 · 부가세는 이 환율로 계산된다.
   이번 주 과세환율과 은행(수출입은행) 환율의 차이, 주별 흐름 차트. 직구 계산기(/calc)도 과세환율을 쓸 수 있게.
2. 통계청 KOSIS 소비자물가 중 여행 품목 — "국제항공료" · "해외단체여행비" 월별 지수.
   작년 대비 · 몇 월이 싼 편인지 차트, 환율 차트와 나란히 비교.
3. 한국은행 ECOS 수입물가지수 — 월별. 환율이 오르면 수입물가가 따라 오르는 관계를 같은 차트에.

사용자는 지금 자는 중이라 질문에 답할 수 없습니다. 묻지 말고 판단해서 진행하고, 판단한 내용은 PR 본문과 보고에 적으세요.
역할 · 파일 범위는 .agents/orchestration/team.md, 규칙은 AGENTS.md 를 따르세요.

## 진행 방식
- 자료 하나 = 작업 하나 = PR 하나 (3개 PR). 작업 번호가 겹치지 않게 순서대로 spec:new (먼저 만든 폴더를 main 에 없어도 고려해 번호를 직접 확인).
- 각 작업: request.md 에 위 원문 + 해당 자료 설명 → plan.md → test(먼저 FAIL) → builder 구현 → test PASS → checks.sh → PR.
- 시작 전에 각 API 의 공식 명세(요청 주소 · 파라미터 · 응답 형식 · 키 발급 조건 · 호출 한도)를 공식 문서에서 확인해 plan.md 에 출처와 함께 적으세요.
  관세청은 UNI-PASS 오픈API 또는 공공데이터포털의 과세환율 API, KOSIS 는 공유서비스 OpenAPI, ECOS 는 ecos.bok.or.kr OpenAPI.
- 기존 구조를 따르세요: apps/api/src/features/fx · prices (수집 · 저장 · 라우트), apps/web 의 기존 차트 · 페이지 패턴, docs/domain/ 갱신.

## 알고 시작할 것 (설치 에이전트가 확인함)
- **API 키가 아직 없습니다.** 관세청 · KOSIS · ECOS 키는 사용자가 회원가입 후 직접 발급해야 합니다.
  - 키는 환경변수(예: KCS_KEY · KOSIS_KEY · ECOS_KEY)로 읽고, 키가 없으면 수집을 건너뛰고 화면은 빈 값 · "준비 중"으로 보여 주게 만드세요. 숫자를 지어내지 마세요.
  - 테스트는 공식 문서의 응답 예시로 만든 fixture 로 하세요. 실제 호출 성공 여부는 "키 발급 후 확인 필요"로 남기세요.
  - apps/api/.dev.vars.example 에 키 이름(값 없이)과 발급처 주석을 추가하세요. 보호 목록은 .dev.vars 만 막고 .example 은 막지 않습니다.
- **수집 일정은 wrangler 를 바꾸지 말고 기존 크론에 붙이세요** (apps/api/src/index.ts 의 CRON).
  - 과세환율(주간) → 평일 12:00 KST 회차(fxDaily)에서 함께 받기 (이미 받은 주는 건너뛰기).
  - KOSIS · ECOS(월간) → 매달 1일 회차(pricesMonthly)에서 함께 받기. 월 자료는 발표가 늦으니 최근 몇 달을 다시 받아 덮어쓰기.
  - 기존 환율 수집이 새 수집 실패에 영향받지 않게 분리하세요.
- **DB 스키마(apps/api/src/db/schema.ts)와 마이그레이션 폴더는 보호 파일**입니다.
  - 새 테이블이 필요하면 새 마이그레이션 + schema.ts 변경을 PR 에 넣되, "보호 파일 변경 — 사람 승인 필요"를 PR 본문 맨 위에 적고 무엇을 왜 바꿨는지 설명하세요.

  - 가능하면 세 자료가 테이블 하나(예: 지표 · 날짜 · 값 형태의 시계열)를 함께 쓰게 설계해, 보호 파일 변경을 한 PR(첫 번째)에만 모으세요. 나머지 PR 은 그 위에 쌓으세요.
