# 계획

## 무엇을 · 왜
- test 가 새 테스트를 쓸지를 작업 종류로 나누는 규칙을 team.md test 절과 verdict.md "디자인 PR 판정"에 적는다. 모양만 바뀌는 작업(모서리 · 투명도 등)에도 새 테스트를 쓰느라 시간을 썼다.
  - 보이는 값만(색 · 모서리 · 투명도 · 그림자 · 테두리): 새 테스트 없음 · 로컬 e2e 없음
  - 크기 · 간격 · 위치 · 줄바꿈: 새 테스트 없음 · 기존 기능 테스트가 main PR 전체 e2e 에서 돎
  - 숫자 · 동작 · 문구 규칙 변경 · 사용자의 새 조건: 요구마다 기능 테스트를 새로 씀
- 기존 줄 "request.md 원문의 요구마다 테스트를 하나 이상 만든다"는 세 번째 경우에만 적용되도록 바꾼다.
- team.md 에 claude-desktop 절을 더해 "규칙 변경은 claude-desktop 이 문서를 직접 고치고, 팀에는 바뀐 뒤 알린다"를 적는다(사용자 지시).

## 애매한 곳
- 종류가 애매하면 테스트를 덜 쓰는 쪽으로 본다. (가정 — 사용자가 테스트에 쓰는 시간을 줄이려 함)
