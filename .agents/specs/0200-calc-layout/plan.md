# 계획

## 무엇을 · 왜
- 직구 계산(`/calc`) 배치를 사용자가 고른 시안 B 로 바꾼다 (#235).
- 넓은 화면
  - 입력 칸을 두 줄로: 통화 | 물건 값 · 보내는 곳(가로 전체) · 국제 배송비 | 관세율
  - 입력 묶음과 결과 칸의 높이를 같게 둔다.
- 그 아래 가로 전체로 **수입물가와 환율**을 둔다: 큰 숫자 두 개 · 차트 · 선 끝 금액.
- 그 아래 **이번 주 과세환율**을 둔다 (지금은 둘이 2단이고 과세환율이 먼저).
- 휴대폰은 위아래로: 입력 → 결과 → 수입물가와 환율 → 이번 주 과세환율.
- 값을 넣어도 칸이 움직이지 않게 한다: 결과 칸 크기를 고정하고, 결과 · 오류 문구가 바뀌어도 칸 크기는 그대로 (넘치는 글은 칸 안에서).
- 처음 들어오면 예시 값을 넣어 결과가 바로 보이게 한다: 통화 USD · 물건 값 180 · 보내는 곳 미국 목록통관 · "예시" 표시.
- 환율을 못 받으면(서버 끊김 · 달러 환율 없음) 지금 상태(빈 입력 · 안내) 그대로 둔다.

## 애매한 곳
- 예시 값은 처음 통화가 달러일 때만 넣는다. `/calc?currency=JPY` 처럼 다른 통화로 들어오면 지금처럼 빈 칸이다 (가정 · 180 은 달러 기준 예시).
- "예시" 표시: 물건 값 칸 옆 작은 글 "예시 값 — 바꿔 넣어 보세요". 사용자가 한 칸이라도 고치면 사라진다 (가정).
- 큰 문장(사진 위 제목)도 예시 값 결과로 보인다 (가정 · 지금도 입력에 따라 바뀜).
- 넓은 화면 결과 칸 높이: 입력 묶음과 같은 높이 (grid `items-stretch`) · 휴대폰은 결과 칸 최소 높이를 고정해 문구가 바뀌어도 아래 칸이 밀리지 않게 (가정 · 시안 B)
- 시각 세부(간격 · 글자 크기 · 색)는 참고 파일 `.tmp/calc-drafts/chosen-B-reference.html`(저장소 루트 .tmp) 의 B 를 따른다.

## 허점
- 계획 밖 변경: 없음 (import-calc · e2e · 이 폴더만). 새 파일 `lib/example.ts` · `example.test.ts`.
- 고정 크기: 결과 칸은 휴대폰 30rem 고정(넘치는 글은 칸 안 스크롤) · 넓은 화면은 입력 묶음과 같은 높이(결과 내용을 겹쳐 놓아 행 높이에 영향 없음). 입력의 힌트 · 오류는 같은 자리(2줄 높이)를 써서 오류가 떠도 입력 칸이 안 커짐. 휴대폰은 힌트 자리 때문에 입력 칸 사이가 조금 넓음.
- e2e 고정 검사는 "입력 칸 위 → 수입물가 칸" 거리로 비교. 맨 위 큰 문장은 입력에 따라 줄 수가 바뀔 수 있음(칸 밖 · 이번 작업 범위 아님) — 필요하면 큰 문장도 고정해야 하는지 lead 판단.
- 선 끝 금액은 HTML 글자(휴대폰에서도 같은 크기) · 위치는 viewBox 비율. 예시 값은 처음 한 칸을 고치면 표시만 사라지고 값은 남음. 단위 테스트는 순수 함수(예시 · 큰 숫자)만 — 훅 동작은 e2e 로 확인.
- 캡처: .tmp/calc-wide.png · calc-phone.png (커밋 안 함). 통화 · 환율 없음은 기존 코드 그대로(CalcForm 안 그림).
- lead 미리보기 확인: 넓은 화면에서 900(한도 넘음)을 넣으면 칸은 그대로(402px)인데 사진 위 큰 문장이 2줄 → 3줄이 되어 아래 칸이 7px 밀림 → 큰 문장에 세 줄 높이를 미리 잡음(sm 이상 · 휴대폰은 위치 변화 없음 확인).
