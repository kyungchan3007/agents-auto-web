# Trace — 과정 기록

> 판단과 이유를 작업하면서 남긴다. 나중에 재구성하지 않는다

| 순서 | 단계 | 한 일 | 판단 · 이유 |
| --- | --- | --- | --- |
| 1 | 조사 | `/geo` 응답 · 방문 기록 코드 · robots.txt · `_routes.json` 확인 | 기록 장치는 정상 (Googlebot 6회 기록) · 기록 시작이 11-05 라 하루치 · AI 쪽 0 은 실제로 방문이 없는 것 |
| 2 | 제안 | AI 검색에 직접 질문하는 측정 제안 → 사용자 "추가해" | 기다리는 측정만으로는 0 이 계속됨 · 직접 묻는 측정은 사이트가 인용되는지를 바로 셈 |
| 3 | 설계 | gsc-sync 와 같은 Actions → D1 구조 · 질문은 기준선 24개 | 비교 가능 · Worker 에 키 · SDK 를 넣지 않음 |
| 4 | 구현 | 스키마 · 마이그레이션 · 해석 함수 · 스크립트 · 계약 · 요약 · 화면 · 워크플로 | Claude 는 공식 SDK(1.6.0)의 타입으로 응답을 읽음 · 다른 서비스는 모르는 모양을 0 으로 |
| 5 | 확인 | 키 없이 스크립트 실행 · 타입 검사 · 단위 테스트 | 키가 없으면 측정 안 함으로 남고 값을 만들지 않음 |

## 허점
- scripts/ 폴더는 tsconfig include 밖이라 타입 검사가 게이트에 없다 (gsc-sync.ts 도 같음). 이번에는 따로 tsc 로 확인했다. 두 번 나오면 tsconfig 에 넣는다
