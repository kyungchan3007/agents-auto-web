## 할 일
1. `apps/web/playwright.config.ts` 에서 병렬을 늘린다.
   - 지금: `workers` 설정 없음 → CI(ubuntu-latest, 4코어) 기본값은 절반(2)이다. `fullyParallel` 도 없어서 파일 단위로만 나뉜다.

   - 이 파일은 **보호 파일이 아니다** → 라벨 없이 진행할 수 있다.
2. 시간을 실제로 재서 PR 본문에 적는다.
   - 기준: 직전 Full 게이트 시간(예: 0231 = 약 22분, 13:51→14:14)과 비교한다.
   - 병렬을 올려 생기는 불안정(같은 테스트가 가끔 실패)이 있으면 그 spec 이름과 증상을 적는다. 숨기려고 retries 를 늘리지 않는다.
3. (선택) 그래도 10분이 넘으면 shard(잡 2~4개로 나누기)를 제안만 한다.
   - `.github/workflows/checks.yml` 은 **보호 파일**이라 사람이 harness-approved 라벨을 달아야 한다. 이번 PR 에서 바꾸지 말고 PR 본문에 제안으로만 남긴다.
