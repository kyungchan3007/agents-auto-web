# PRD — 무엇을 · 왜

> 원문(request.md)을 옮긴 파생 문서. 요구 충족 판정 기준은 언제나 원문이다

## 문제
- 회사 링크(owner 가 아닌 토큰)로 어드민에 들어오면 첫 진입 안내 창(온보딩)이 떠서 이력서 검토하는 사람이 바로 내용을 보지 못한다.
- 회사 링크에도 작업실 · 알리기 · 유입 · 인스타 유입까지 여섯 화면이 다 보인다.

## 목표
1. 회사 세션은 안내 창 없이 링크를 누르면 바로 화면을 본다. 대신 넣는 안내 문구 없음.
2. 회사 세션 메뉴는 GEO 측정(/geo) · 만드는 방식(/how) 두 개 + 사이트로 가기. 넓은 화면 사이드 · 휴대폰 위 메뉴 · 찾기(⌘K) 목록 · 숫자 단축키 모두 같은 두 개. 로고 링크 = /geo. owner 는 지금 그대로 여섯 개.
3. 메뉴는 owner 판정(/session)을 받기 전에는 두 개로 그리고, owner 로 확인되면 나머지를 더한다(여섯 개가 보였다 사라지지 않음 · 메뉴 칸 높이 · 위치 흔들림 없음).
4. 서버(worker)에서 막음: 회사 세션이 /log · /marketing · /traffic · /instagram(하위 · 정적 파일 변형 포함)을 열면 /geo 로 302. 그 화면만 쓰는 /bff 자료(activity · tasks · ga4 · ig)는 403. /geo · /how 가 쓰는 /bff 는 그대로.
5. 첫 화면: 회사 링크(?t=)로 들어오거나 / 로 오면 회사 세션은 /geo. 링크 주소에 막힌 경로가 들어 있어도 쿠키를 심은 뒤 /geo 로. owner 는 지금처럼 / → /log.
6. (추가 지시로 바뀜) owner 가 아닌 토큰은 접속 기록을 남기지 않는다(worker recordVisit · API admin-visits POST 를 부르지 않음) — "열람 기록이 남지 않도록" 이 사실이 되게. 만드는 방식의 owner 전용 방문 기록 칸은 그대로(지난 기록만 보이거나 빔 · 새 기록 안 쌓임).
7. 문구: 회사(owner 아닌) 세션에서 넓은 화면 사이드바 아래 빈 곳(로그아웃 위)에 원문 두 문장 그대로 작은 글씨 — "채용 담당자분들을 위한 데모 링크입니다. 열람 기록이 남지 않도록 모든 분께 같은 링크 하나를 드리고 있습니다." 휴대폰(사이드바 없음)은 본문 맨 아래 한 번. owner 에겐 안 보임(data-viewer 로 거름 · 첫 그림부터). 문구 때문에 메뉴 · 본문 위치가 흔들리지 않음.
8. 토큰: 회사마다 따로 → 채용 담당자 공용 토큰 하나(이름 recruiter). scripts/admin-token.mjs 에서 add recruiter 가능(apply-<회사>-<날짜> 이름 전제 · 회사 전용 흔적 정리) · 이력서에 오래 붙으므로 --exp 를 길게 줄 수 있게(지원 여부 확인 · 없으면 고침). 브라우저 쿠키 유효 기간(REVIEWER_MAX_AGE)은 그대로. 이미 나간 회사 토큰을 지우거나 막지 않음(사용자가 터미널에서 remove).
9. 토큰 값 · 링크는 코드 · 로그 · 기록에 쓰지 않음. 실제 recruiter 링크 만들기는 사용자가 맥 터미널에서.

## 비목표
- owner 화면 · 메뉴 변경 없음. 토큰 발급 · 쿠키 형식 변경 없음. 운영 사이트(main) 반영 없음.

## 애매한 곳
- 숫자 단축키: 회사 세션은 두 화면의 지금 키(GEO 2 · 만드는 방식 3)를 그대로 쓰고 나머지 키는 동작 안 함 (가정 · 같은 키가 세션마다 다른 화면이 되지 않게).
- /bff/status 는 어드민 화면 코드에서 쓰는 곳을 builder 가 확인해 막힌 화면 전용이면 403, 아니면 그대로 (가정).
